## Three Highest Technical Risks (ranked, post-correction)
1. **R11 — Deadline pressure vs. scope.** With ~2 days until submission, attempting high-risk stretch features (video analysis, barbell scanning) instead of hardening the MVP is the single biggest threat to delivering a working, gradable application.
2. **R10 — `gpt-6-luna` multimodal capability unverified.** The WOD Scanner is now a priority MVP feature; if the course-approved model cannot handle image input, this blocks a required feature and forces a fallback-model approval mid-build.
3. **R1 — Video Technique Analysis false precision** (retained, now scoped to stretch-only). Still a real risk if attempted, which is why it must not be promised in the final report unless implemented and tested.

Retained from the original Phase 0 audit, still applicable: R2 (barbell weight fabrication), R3 (WOD Scanner misreads), R4 (corrective engine inheriting upstream errors), R5 (nutrition scope drift), R6 (secret exposure), R8 (uncontrolled API cost), R9 (knowledge-base gaps). R7 (unpublished rubric) is now resolved — see RUBRIC_COMPLIANCE.md.
